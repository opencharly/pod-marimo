# 2026.320.2210 — fix(require): advance the layer-cuda pin past the CDI driver-shadowing fix

## Summary

`layer-cuda` v2026.290.2052 → **v2026.320.2103**, producer-first — the tag existed before this pin
moved, and it is the one that carries the CDI driver-shadowing fix (opencharly/layer-cuda#19).

**Why one line matters here.** `layer-cuda` v2026.290.2052 still requires the **pre-fix**
`layer-nvidia` commit:

```
$ gh api repos/opencharly/layer-cuda/contents/charly.yml?ref=v2026.290.2052 --jq .content | base64 -d | grep -n 'layer-nvidia:'
13:            - '@github.com/opencharly/layer-nvidia:7766a9d06ec5fe8c276c091a68fb72cea12688e3'
```

so composing this pod drags the pre-fix driver user-space in, AND it makes any box that pins the
current GPU stack NEXT TO this pod resolve one candy at two refs — which charly refuses. Measured
in opencharly/distro-cachyos, whose `versa` box pins `layer-cuda:v2026.320.2103` +
`layer-nvidia:v2026.320.1938` and composes `pod-marimo:v2026.290.2104`:

```
candy github.com/opencharly/layer-nvidia resolved to multiple git tags with differing content
within one scope (box=versa); using newest referenced v2026.320.1938 (from …);
also referenced 7766a9d06ec5… (from …; scopes: box=versa)
```

That diagnostic names the losing ref only because opencharly/sdk#549 landed today; before it, the
message named the winner alone and finding this two-hop `require:` chain took bisecting an
eighteen-candy box.
